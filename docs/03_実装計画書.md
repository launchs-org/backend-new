# Launchs-org 実装計画書

## 実装方針

- 言語: Go（全バックエンドコンポーネント）
- フレームワーク: Echo（Backend）
- ORM: GORM + AutoMigrate
- ワークフロー: Temporal
- Kubernetes 操作: 全てワークフロー経由
- インターフェースを要求する設計（DI）でテスト容易性を担保
- 各コンポーネントは独立したコンテナとしてスケール可能

```go
// watcher/src/collector/log_collector.go
type LogCollector struct {
    buffer      []model.ContainerLog
    mu          sync.Mutex
    flushTicker *time.Ticker
    repo        LogRepository
    interval    time.Duration // 環境変数 LOG_FLUSH_INTERVAL_SEC
}

func (c *LogCollector) Start(ctx context.Context) {
    for {
        select {
        case <-c.flushTicker.C:
            c.flush(ctx)
        case <-ctx.Done():
            c.flush(ctx) // 終了前に残りをフラッシュ
            return
        }
    }
}
```

```typescript
// frontend/src/api/client.ts
const BASE_URL = '/api/v1'

async function request<T>(
  path: string,
  options?: RequestInit
): Promise<T> {
  const token = getJWT() // 既存の JWT 取得関数
  const res = await fetch(`${BASE_URL}${path}`, {
    ...options,
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${token}`,
      ...options?.headers,
    },
  })
  const json = await res.json()
  if (json.error) throw new ApiError(json.error.code, json.error.message)
  return json.data
}

// frontend/src/api/logs.ts
export async function getContainerLogs(
  projectId: string,
  containerId: string,
  cursor?: string,
  limit = 100,
  podName?: string
): Promise<{ logs: Log[]; next_cursor: string }> {
  const params = new URLSearchParams({ limit: String(limit) })
  if (cursor) params.set('cursor', cursor)
  if (podName) params.set('pod_name', podName)
  return request(`/projects/${projectId}/containers/${containerId}/logs?${params}`)
}

export async function getBuildJobLogs(
  projectId: string,
  buildJobId: string,
  cursor?: string,
  limit = 100
): Promise<{ logs: Log[]; next_cursor: string }> {
  const params = new URLSearchParams({ limit: String(limit) })
  if (cursor) params.set('cursor', cursor)
  return request(`/projects/${projectId}/build-jobs/${buildJobId}/logs?${params}`)
}
```

## スケーリング考慮点

### 冪等性の担保
- Kubernetes リソース名を決定論的に生成（`{name}-{id-short}`）
- `CreateOrUpdate` パターンで複数 Controller が走っても安全

### デッドロック防止
- Temporal の `WORKFLOW_ID_REUSE_POLICY` を `ALLOW_DUPLICATE_FAILED_ONLY` に設定
- 同一コンテナへの同時ワークフロー実行は DB のキューで管理
- キュー上限超過時は即座に `QueueFullError` を返す

### ログ・メトリクスの書き込み負荷
- ログはバッファリングして一括 INSERT（デフォルト3秒）
- メトリクスは15秒ごとの収集で書き込み頻度を制限
- container_status_histories は常に最新100件のみ保持

### Watcher の監視効率
- `launchs-managed=true` ラベルで全 Namespace を一括監視
- Kubernetes Informer/Watch API を使用してポーリングを最小化
